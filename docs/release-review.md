# 发布前代码审查

## 0.2.0 发布候选复查（2026-10-21，尚未发布）

本次复查覆盖账号与旧凭据迁移、角色/来源切换、共享定位与本机直连、悬浮窗、自动弱网、辅助程序清理、发布配置和用户文档。按用户要求只进行源码检查和编译，不运行测试、应用或游戏网络操作；静态复查不能证明没有运行时问题。

本轮修复与准备：

- 坐标页切换角色、游客账号管理选择角色和删除正在使用的本机账号时，先关闭弱网，再断开旧定位，避免旧角色的弱网状态跟随新角色。
- 本机旧凭据过期、重启后没有内存角色缓存时，重新登录会同时核对安全存储中原先保存的角色标识。身份无法确认时仍保留原凭据，用户可新增账号后再移除旧记录。
- 辅助程序报错时先撤销就绪状态，再通知界面，避免坐标监听器在错误回调中向失效的辅助程序发送消息。
- 手动重新连接开始时立即取消旧的自动重试计时器，避免等待旧连接关闭期间又触发一次自动重连。
- 源码版本准备为 0.2.0+7；正式发布仍须使用对应标签和流水线，不能把旧原生 EXE 配上新 AOT 文件当作正式版。
- 更新中文发布说明并删除旧手动弱网文案。Release 不再附加自动生成的英文更新记录。
- 正式 Android 发布缺少签名时明确失败，不再静默发布临时签名 APK；手动构建仍可保留测试用途。

仍须保留的限制与验收边界：

- 自动弱网可能误判，不能保证在所有区域、战斗或界面操作下均正确；最大时长和手动解除继续作为恢复方式。
- Windows 无障碍语义树暂时禁用以规避已知 Flutter 原生崩溃，屏幕阅读器控件识别受限。
- 本轮不启动应用，也不读取或改动真实账号、游戏连接、驱动服务；风险确认记忆、进出区域、断线、UAC 和退出卸载仍需实际使用验收。
- Linux / Android 未在本机完成对应平台构建或运行；发布前须确认正式签名可用，并由跨平台构建流水线验证。
- Linux 的悬浮窗快捷键只在主界面获得焦点时响应，不是系统全局快捷键；跟随游戏窗口与自动弱网仅支持 Windows。
- 本轮禁止推送、打标签、触发远程工作流、创建 Release 或发布正式 0.2.0；等待用户下一步明确指示。

本轮验证结果：

- 4 个改动 Dart 文件格式检查通过；网络辅助程序目录的 13 个 Python 文件仅进行 AST 语法解析，通过且未执行测试。
- `pubspec.yaml` 与发布工作流 YAML 解析通过。
- Windows Dart AOT 构建通过，注入版本为 `v0.2.0-preflight`。第一次尝试因 Objective-C 依赖的陈旧 hook 缓存路径失败，定向清除该构建缓存后重试成功；没有因此更改产品代码。
- 完整 Windows 原生 runner 构建未验证：本机缺少 CMake、MSBuild、cl 工具链。没有安装大型工具链，也没有用 AOT 结果替代完整原生构建结论。
- 本地预检包如复用既有 EXE，其原生文件版本仍可能是旧版；该包仅用于预检，不是可正式发布的 0.2.0。正式发布须由对应版本标签的完整流水线重新生成原生 EXE 和各平台安装包。
- 未启动客户端、网络辅助程序、游戏或驱动；未进行自动化测试和真实账号迁移操作。中文更新说明已准备在 `packaging/release-notes.md`。

本轮审查范围为 Windows 自动弱网、悬浮窗、辅助程序生命周期、导航、发布脚本与文档。不是全平台运行验证，也不能证明自动识别不会误判。

## 已清理

- 删除蹭缝页面、估算算法及对应测试，调整导航顺序，更新说明。
- 删除没有调用方的 `SystemApi` 健康检查包装及依赖装配；保留区域名称和高度范围仍使用的后端客户端。
- 删除已经没有发送方的旧 `stopped` 控制消息处理。
- 逐帧时序、哈希及指定帧原始字节默认不采集。诊断日志改为显式开启，日志写入单独模块，避免使用连接状态锁进行磁盘写入。
- 每次运行的网络日志按约 8 MiB 轮换，保留当前文件和上一文件。写日志失败不再导致网络处理退出。
- 清理了测试中已失效的导航与旧开关预期，发布流程标题使用 Zipliner Client。

## 保留的代码

权限检查、辅助程序身份确认、控制通道认证、重连超时、积压数据放行、驱动退出与共享驱动占用判断都属于必要的保护逻辑。

坐标采集记录是滑索采集功能的用户选项，不是默认启用的调试日志。调试构建的控制台输出、测试替身以及显式设置环境变量才生效的开发窗口位置选项，均不参与默认发布运行流程。

没有在发布前重写整个网络引擎。`helper.py` 仍集中处理资源生命周期、控制命令和连接转发，是后续重构重点；本轮仅分离日志职责，避免同时大改协议判定与退出流程。

## 详细日志

排查问题时，完全退出旧客户端，在启动新客户端前设置环境变量 `ZIPLINER_NETWORK_DIAGNOSTICS=1`。辅助程序才会记录逐帧信息及先前限定的原始字节。该选项不保存在用户设置中；不设置时默认关闭。详细日志仅供主动排查问题使用，不应作为普通发布环境的默认启动设置。

## 发布前仍需确认

- Windows 启动闪退的临时规避：2026-10-20 的三次原生崩溃均为 `flutter_windows.dll + 0x3c06a / 0xc0000005`。发布 DLL 与 SDK 缓存 DLL 哈希一致；使用对应 PDB 定位到 `flutter::AccessibilityBridge::CreateRemoveReparentedNodesUpdate + 0xba`，与 [Flutter #175041](https://github.com/flutter/flutter/issues/175041) 相同。主进程和独立悬浮窗共用 `ClientWidgetsBinding`，在 Windows 暂不生成无障碍语义树，避免进入该原生路径；其他平台保持原行为。Windows 屏幕阅读器暂不能读取控件信息。此为兼容性规避，不是上游引擎修复；更换到经验证已修复的引擎后应移除。构建通过后仍需用户实际启动确认不再闪退。

- 按当前用户要求，本轮只进行编译和源码检查，不运行自动化测试、应用程序或真实游戏网络操作。风险确认的跨重启记忆、关闭后再次开启、断线恢复、退出驱动清理仍需在游戏中验收。
- 自动识别依赖消息形状与坐标证据，仍可能误判。编译成功不能视为识别准确率验证。
- 本地预检包使用 `APP_VERSION` 注入版本；本轮 `pubspec.yaml` 已准备为 0.2.0+7，但复用的原生 EXE 仍是旧文件版本。正式发布时应统一应用版本、文件版本与标签，不能直接将预检包当作正式版本。
- 未进行远程发布、推送标签、更新依赖或跨平台打包。本轮没有更换 WinDivert 架构，系统兼容性与安全软件拦截仍需保留用户指引。
